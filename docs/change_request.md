# ツール改修記録

本書は運用ツールの改修内容、変更理由、影響範囲、および検証結果を記録した台帳である。

---

## 課題1（CR-1）：health_check.sh タイムアウト追加と本文・終了コード厳密化

- **変更要求**：
  - 接続タイムアウト（`--connect-timeout 3`）と全体タイムアウト（`--max-time 5`）を追加し、サーバー無応答時のプロセス停止を防止する。
  - レスポンス本文に指定文字列が含まれているかを固定文字列検索（`grep -qF`）で検証する。
  - 終了コードを 0（正常）、1（異常検知: 404/本文不一致）、2（取得失敗: 接続拒否/タイムアウト）に厳密に分類する。
- **変更前の動作**：
  - タイムアウト未指定のため、サーバーハング時に長時間応答待ちが発生する状態だった。
  - 本文の検証がなく、HTTP 200 であればエラー画面でも正常扱いとなっていた。
- **変更したファイルと箇所**：
  - `scripts/health_check.sh`（引数バリデーション、curlオプション、3段階判定処理）
- **変更理由**：
  - 定期実行（systemd timer）がタイムアウト待ちで滞留するのを防ぐため。
  - Webサーバー障害時の初動切り分け（コンテンツ問題か、インフラ/NW問題か）を終了コードで即座に判断できるようにするため。
- **影響する処理・現実装の制限事項（今後の改善課題）**：
  - 第2引数（期待する本文文字列）が必須となった。呼び出し側（systemd service など）で引数の見直しが必要。
  - 現実装では `[ $CURL_EXIT -ne 0 ]` の場合に終了コード 2 とともに一律で `[FAIL] 通信失敗: 接続拒否またはタイムアウト (curl終了コード: $CURL_EXIT)` を出力する。そのため、F07（systemdの `PATH=/dummy` 誤設定障害）のようにコマンド実行環境の問題で `curl` 自体が見つからない場合（`curl終了コード: 127`）もメッセージ文面上は「通信失敗」と表示される（実際の原因切り分けは直前の `mktemp: コマンドが見つかりません` および `curl終了コード: 127` から特定）。
  - F07の検証を通じて得られた知見として、① `mktemp` の実行結果検証、② `curl` コマンドの事前存在確認（`command -v`）、③ `curl` の終了コード `127` 等のコマンド実行環境エラーと通信障害（コード `7` / `28`）の診断メッセージ分離、④ 一時ファイルの後始末を `trap` で管理する処理の4点を今後の拡張課題とする。
- **正常時の試験と結果**：
  - パターン1（正常URL・期待本文一致）：終了コード 0（正常）
- **異常時の試験と結果**：
  - パターン2（本文不一致）：終了コード 1（異常検知）
  - パターン3（HTTP 404）：終了コード 1（異常検知）
  - パターン4（ポート未開放/接続拒否）：終了コード 2（取得失敗）
  - パターン5（応答なし/タイムアウト）：終了コード 2（取得失敗、約3秒で復帰）
  - ※詳細エビデンス：`evidence/T11_cr1_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/health_check.sh scripts/health_check.sh`（または `patch -R -p0 < evidence/CR1.diff`）
- **差分ファイル**：
  - `evidence/CR1.diff`

## 課題2（CR-2）：backup_dir.sh の改修（保存先引数化・事前検証）および復元diff照合試験

- **変更要求**：
  - バックアップ保存先ディレクトリを引数（第2引数）で指定可能にする（スクリプトの実装範囲は事前検証と `tar.gz` 作成までとし、復元と `diff` 照合は検証手順として実施）。
  - バックアップ対象不在時、保存先ディレクトリ作成失敗時、および保存先への書き込み権限不足時に、エラーを出力して終了コード 2 で終了する。
  - 試験手順として別ディレクトリへの展開（復元）を行い、元データとの内容一致（`diff -r` 差分なし）および改変検知を確認する。
- **変更前の動作**：
  - 保存先が固定されており、保存先ディレクトリの書き込み権限や存在チェックが不足していた。
- **変更したファイルと箇所**：
  - `scripts/backup_dir.sh`（引数チェック、対象ディレクトリ存在確認、保存先ディレクトリ作成成否判定、保存先書き込み権限 `-w` 検証、`-C` オプションによる相対パスでの `tar` 圧縮処理）
- **変更理由**：
  - 実行環境やストレージ構成に応じて保存先を柔軟に指定でき、かつ絶対パスを含まない相対パスでアーカイブ内の格納先を管理して任意の展開先配下への復元を容易にするため。
  - 対象不在や保存先への書き込み権限不足（実行ユーザーの権限に基づく判定）の際に、`tar` を実行する前の事前検証で処理を安全に中断し、不要なエラーや空ファイルの生成を防ぐため。
- **影響する処理・実行方式と現実装の制限事項**：
  - 第1引数（対象ディレクトリ）と第2引数（保存先ディレクトリ）の指定が必須となった（現実装は `-z` による第1・第2引数の空欄チェックであり、`[ "$#" -ne 2 ]` による3引数以上の余剰引数エラー判定は今後の改善課題）。
  - 保存先の書き込み権限チェック（`[ ! -w "$DEST_DIR" ]`）は、**スクリプトを実行したユーザーの権限**に基づいて判定される。そのため運用・試験時は以下の通り実行方式を使い分ける：
    1. 一般ユーザーでバックアップする場合：一般ユーザーで読み取り可能な対象と書き込み可能な保存先を指定する。
    2. root権限でバックアップする場合：`/etc/nginx` 等の特権ディレクトリを対象とする際は `sudo` を使用し、rootとして書き込み可能な保存先を指定する（root実行時は通常の権限ビットによらず書き込み可能と判定される）。
    3. 権限不足の試験（T12パターン4）：root所有 `755` の `/srv/backup_ro` に対して一般ユーザー（`sudo` なし）で実行し、`[ ! -w ]` 分岐による終了コード 2 を確認する。
  - `tar` コマンド自体の失敗時は終了コード 1 を返すが、`tar` 実行途中の異常中断時に作成途中の不完全ファイルを自動削除する処理（一時ファイル `.tmp` への書き出しと成功時の `mv`、および `trap` による削除）は未実装であり、今後の拡張課題とする。
- **正常時の試験と結果**：
  - パターン1（`/etc/nginx` を指定した保存）：終了コード 0（アーカイブ正常生成）
  - パターン5（別手順でのアーカイブ展開・差分照合）：`diff -r --no-dereference` の終了コード 0（元データと完全一致）
- **異常時の試験と結果**：
  - パターン2（存在しない対象ディレクトリ `/not_exist_dir` 指定）：終了コード 2（対象不在で中断）
  - パターン3（作成不可ディレクトリ `/proc/invalid_backup` 指定）：終了コード 2（`mkdir -p` 失敗分岐で中断）
  - パターン4（root所有 `755` の `/srv/backup_ro` に対し一般ユーザー `user` で実行）：終了コード 2（`[ ! -w ]` 書き込み権限なし分岐で中断）
  - パターン6（復元ファイルを意図的に改変した後の照合）：`diff -r --no-dereference` の終了コード 1（差分検知）
  - ※詳細エビデンス：`evidence/T12_cr2_backup_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/backup_dir.sh scripts/backup_dir.sh`（または `patch -R -p0 < evidence/CR2.diff`）
- **差分ファイル**：
  - `evidence/CR2.diff`

## 課題3（CR-3）：disk_check.sh の改修（設定ファイル分離・引数上書き・入力値バリデーション）

- **変更要求**：
  - 監視対象マウントポイントおよび警告・重大閾値（パーセント）を外部設定ファイル（`/etc/ops/disk_check.conf`）から読み込む構成に変更する。
  - スクリプト実行時の位置引数（`$1`: 監視対象マウントポイント、`$2`: WARN閾値、`$3`: CRIT閾値）によって、設定ファイルの値を用途に応じて一時的に上書き可能にする（T13では設定ファイル読み込みと `$2`（WARN閾値）の上書き［`$1` は設定値と同じ `/` を指定］を検証し、`T07-3` で `$1` に存在しないパスを指定した異常系を確認。設定値とは異なる実在マウントポイントを `$1` に指定した正常系上書き試験、および `$3` の個別上書き試験は未実施・今後の拡張項目とする）。
  - 設定ファイル不在・読み取り不可時、閾値が数値以外または範囲外（1〜100以外）の場合、および警告閾値が重大閾値以上（`WARN >= CRIT`）の場合は、終了コード 2（取得失敗）で安全に終了する。
  - セキュリティ対策として `source` や `.` による直接読み込みを禁止し、設定ファイルを1行ずつ解析・バリデーションする方式とする。
- **変更前の動作**：
  - 閾値や監視対象がスクリプト内にハードコードされており、環境や運用要件に応じた閾値変更のたびにスクリプト本体を直接編集する必要があった。
- **変更したファイルと箇所**：
  - `scripts/disk_check.sh`（設定ファイル存在・読み取り権限チェック、1行パース読み込み、引数による上書き処理、整数・範囲判定、閾値大小関係 `WARN < CRIT` チェック）
  - `/etc/ops/disk_check.conf`（新規作成：パーミッション 600、root所有）
- **変更理由**：
  - 閾値調整時にスクリプト本体のコードを改変する運用リスク（オペミスやバグ混入）を排除するため。
  - 外部ファイル読み込み時の悪意あるコマンドインジェクション（不正実行）を防止し、パーミッション 600（`sudo` 実行前提）で非特権ユーザーによる改ざん・閲覧を防ぐため。
- **影響する処理**：
  - `/etc/ops/disk_check.conf` が `600 root:root` のため、スクリプト実行時は `sudo ./scripts/disk_check.sh` での実行が前提となる（`sudo` なし実行時は読み取り不可として終了コード 2 で終了）。
- **正常時の試験と結果**：
  - Test1（設定ファイル読み込み実行）：終了コード 0（正常）
  - Test2（引数による閾値上書き実行：1%指定）：指定した引数値で判定され終了コード 1（警告検知）
- **異常時の試験と結果**：
  - Test3（設定ファイル不在）：終了コード 2（`Config file not found`）
  - Test4（引数の閾値に文字列 `abc` を指定）：終了コード 2（`invalid_threshold`）
  - Test5（設定ファイルの閾値に文字列 `abc` を指定）：終了コード 2（`Thresholds must be integers.`）
  - Test6 / Test7（引数および設定ファイルで `WARN >= CRIT` となる `95` を指定）：終了コード 2（`warn_not_less_than_crit`）
  - Test8（一般ユーザーで `sudo` なし実行）：終了コード 2（`Config file not readable`）
  - ※詳細エビデンス：`evidence/T13_cr3_config_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/disk_check.sh scripts/disk_check.sh`（または `patch -R -p0 < evidence/CR3.diff`）
- **差分ファイル**：
  - `evidence/CR3.diff`
