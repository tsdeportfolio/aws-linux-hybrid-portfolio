# ツール改修記録

本書は運用ツールの改修内容、変更理由、影響範囲、および検証結果を記録した台帳である。

---

## 課題1（CR-1）：health_check.sh タイムアウト追加と本文・終了コード厳密化

- **変更要求**：
  - 接続タイムアウト（--connect-timeout 3）と全体タイムアウト（--max-time 5）を追加し、サーバー無応答時のプロセス停止を防止する。
  - レスポンス本文に指定文字列が含まれているかを検証する。
  - 終了コードを 0（正常）、1（異常検知: 404/本文不一致）、2（取得失敗: 接続拒否/タイムアウト）に厳密に分類する。
- **変更前の動作**：
  - タイムアウト未指定のため、サーバーハング時に長時間応答待ちが発生する状態だった。
  - 本文の検証がなく、HTTP 200 であればエラー画面でも正常扱いとなっていた。
- **変更したファイルと箇所**：
  - `scripts/health_check.sh`（引数バリデーション、curlオプション、3段階判定処理）
- **変更理由**：
  - 定期実行（systemd timer）がタイムアウト待ちで滞留するのを防ぐため。
  - Webサーバー障害時の初動切り分け（コンテンツ問題か、インフラ/NW問題か）を終了コードで即座に判断できるようにするため。
- **影響する処理**：
  - 第2引数（期待する本文文字列）が必須となった。呼び出し側（systemd service など）で引数の見直しが必要。
- **正常時の試験と結果**：
  - パターン1（正常URL・期待本文一致）：終了コード 0（正常）
- **異常時の試験と結果**：
  - パターン2（本文不一致）：終了コード 1（異常検知）
  - パターン3（HTTP 404）：終了コード 1（異常検知）
  - パターン4（ポート未開放/接続拒否）：終了コード 2（取得失敗）
  - パターン5（応答なし/タイムアウト）：終了コード 2（取得失敗、約3秒で復帰）
  - ※詳細エビデンス：`evidence/T11_cr1_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/health_check.sh scripts/health_check.sh`
- **差分ファイル**：
  - `evidence/CR1.diff`

## 課題2（CR-2）：backup_dir.sh の改修（保存先引数化・事前検証・差分照合）

- **変更要求**：
  - バックアップ保存先ディレクトリを引数（第2引数）で指定可能にする。
  - バックアップ対象不在時や保存先への書き込み不可時に、エラーを出力して終了コード 2 で終了する。
  - 復元検証を行い、元データとの内容一致（diff 差分なし）を確認する。
- **変更前の動作**：
  - 保存先が固定されており、保存先ディレクトリの書き込み権限や存在チェックが不足していた。
- **変更したファイルと箇所**：
  - `scripts/backup_dir.sh`（引数チェック、対象ディレクトリ存在確認、保存先書き込み権限検証、相対パスでの tar 圧縮処理）
- **変更理由**：
  - 実行環境やストレージ構成に応じて保存先を柔軟に指定できるようにするため。
  - 権限不足や対象不在時に処理を無理に進めて空ファイルや中途半端な破損ファイルが生成されるのを防ぐため。
- **影響する処理**：
  - 第2引数（保存先ディレクトリ）が必須となった。
- **正常時の試験と結果**：
  - `/etc/nginx` を指定した保存：終了コード 0（アーカイブ正常生成）
  - アーカイブ復元後の差分照合：`diff -r` の終了コード 0（元データと完全一致）
- **異常時の試験と結果**：
  - 存在しない対象ディレクトリ指定：終了コード 2（対象不在で中断）
  - 書き込み不可ディレクトリ指定（/proc）：終了コード 2（書き込み権限なしで中断）
  - 復元ファイルをわざと改変した後の照合：`diff -r` の終了コード 1（差分検知）
  - ※詳細エビデンス：`evidence/T12_cr2_backup_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/backup_dir.sh scripts/backup_dir.sh`
- **差分ファイル**：
  - `evidence/CR2.diff`

## 課題3（CR-3）：disk_check.sh の改修（設定ファイル分離・引数上書き・入力値バリデーション）

- **変更要求**：
  - 監視対象マウントポイントおよび警告閾値（パーセント）を外部設定ファイル（`/etc/ops/disk_check.conf`）から読み込む構成に変更する。
  - スクリプト実行時の引数指定によって、設定ファイルの値を用途に応じて一時的に上書き可能にする。
  - 設定ファイル不在時、または閾値・対象が無効（空欄や数値以外）な場合は、終了コード 2（取得失敗）で安全に終了する。
  - セキュリティ対策として `source` や `.` による直接読み込みを禁止し、設定ファイルを1行ずつ解析・バリデーションする方式とする。
- **変更前の動作**：
  - 閾値や監視対象がスクリプト内にハードコードされており、環境や運用要件に応じた閾値変更のたびにスクリプト本体を直接編集する必要があった。
- **変更したファイルと箇所**：
  - `scripts/disk_check.sh`（設定ファイル読み込みロジック、引数による上書き処理、数値判定・パス存在チェック）
  - `/etc/ops/disk_check.conf`（新規作成：パーミッション 600、root所有）
- **変更理由**：
  - 閾値調整時にスクリプト本体のコードを改変する運用リスク（オペミスやバグ混入）を排除するため。
  - 外部ファイル読み込み時の悪意あるコマンドインジェクション（不正実行）を防止し、パーミッション 600 で改ざんを防ぐため。
- **影響する処理**：
  - 本番運用時は `/etc/ops/disk_check.conf` の配置および適切な権限設定が前提となる。
- **正常時の試験と結果**：
  - パターン1（設定ファイル読み込み実行）：終了コード 0（正常）
  - パターン2（引数による閾値上書き実行）：指定した引数値で判定され終了コード 0（または 1）
- **異常時の試験と結果**：
  - パターン3（設定ファイル不在・パス不正）：終了コード 2（取得失敗）
  - パターン4（閾値に文字列など無効な値を設定）：終了コード 2（パラメータ異常で中断）
  - ※詳細エビデンス：`evidence/T13_cr3_config_test.txt`
- **変更前に戻す方法**：
  - `cp -a scripts.orig/disk_check.sh scripts/disk_check.sh`
- **差分ファイル**：
  - `evidence/CR3.diff`
